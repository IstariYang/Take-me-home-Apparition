## 新增房产指南 (`Add_New_Home_Guide_CN.md`)

本文档面向已构建好基础 Mod 的用户，说明如何为 Mod 添加新的房产，无需修改任何脚本代码。

## 一、通用流程

无论解锁类型是什么，你需要做以下两件事：

1. **创建必要的 CK 对象**（见下文列表）。
2. **更新对应的 FormList**，将新房产的数据放入正确位置。

核心原则：**所有房产共享统一的 0~65 索引池**，且每个房产的索引由 `TMHA_Index_{房产名}` GlobalVariable 的 Value 决定。

## 二、确定房产基本信息

| 项目 | 说明 | 示例 |
|------|------|------|
| 房产名称 | 游戏内显示的名称 | Severin Manor |
| 所属领地 | 见领地对照表 | Solstheim |
| 解锁方式 | 钥匙 / 任务 / 距离 | 任务 |
| 如果是钥匙型 | 钥匙 EditorID | DLC2RRSeverinManorKey |
| 如果是任务型 | 任务 EditorID | DLC2RR02 |
| 如果是任务型 | 任务完成阶段（0 = IsCompleted） | 0 |
| 房产索引 | 下一个可用索引（建议 = 当前最大索引 + 1） | 17 |

## 四、钥匙型房产

### 需要创建的 CK 对象（共 5 个）

| 序号 | 类型 | EditorID 模板 | 说明 |
|------|------|---------------|------|
| 1 | Message | `TMHA_Name_{房产名}` | 房产显示名称 |
| 2 | GlobalVariable | `TMHA_HoldIndex_{房产名}` | 领地索引（Value = 领地索引号） |
| 3 | GlobalVariable | `TMHA_Index_{房产名}` | 统一房产索引（Value = 房产索引） |
| 4 | FormList | `TMHA_Loc_{房产名}` | 该房产的全部 Location |
| 5 | XMarker | `TMHA_Marker_{房产名}` | 传送目标点（放在房门口或室内） |

### 需要更新的 FormList（共 5 个）

| FormList | 操作 |
|----------|------|
| `TMHA_AllHomeKeys` | 将钥匙 Form 追加到末尾 |
| `TMHA_KeyHomeIndices` | 将 `TMHA_Index_{房产名}` 追加到末尾（**顺序必须与 `TMHA_AllHomeKeys` 一致**） |
| `TMHA_AllHomeMarkers` | 将 XMarker 放入 **索引位置**（如果该位置已有占位，替换；如果长度不足，先扩展 FormList） |
| `TMHA_AllHomeNames` | 将 `TMHA_Name_{房产名}` Message 放入 **索引位置** |
| `TMHA_AllHomeHolds` | 将 `TMHA_HoldIndex_{房产名}` 放入 **索引位置** |

### 可选（强烈建议）

| FormList | 操作 |
|----------|------|
| `TMHA_AllHomeLocationLists` | 将 `TMHA_Loc_{房产名}` 放入 **索引位置**（用于排除当前房产） |
| `TMHA_AllLocationsFlat` | 将所有 Location 追加到末尾（用于判断玩家是否在房产内） |

### 顺序对齐示例

假设你的新钥匙房产索引为 17，`TMHA_AllHomeKeys` 现在长度为 7，新钥匙应放在第 7 位（索引 7），`TMHA_KeyHomeIndices` 的第 7 位必须是对应的 `TMHA_Index_SeverinManor`（Value=17）。其他统一 FormList 中，索引 17 的位置放入对应的数据。

## 五、任务型房产

### 需要创建的 CK 对象（共 6 个）

| 序号 | 类型 | EditorID 模板 | 说明 |
|------|------|---------------|------|
| 1 | Message | `TMHA_Name_{房产名}` | 房产显示名称 |
| 2 | GlobalVariable | `TMHA_HoldIndex_{房产名}` | 领地索引 |
| 3 | GlobalVariable | `TMHA_Index_{房产名}` | 统一房产索引 |
| 4 | GlobalVariable | `TMHA_Stage_{房产名}` | 任务完成阶段（0 = IsCompleted） |
| 5 | FormList | `TMHA_Loc_{房产名}` | Location 子表单 |
| 6 | XMarker | `TMHA_Marker_{房产名}` | 传送目标点 |

### 需要更新的 FormList（共 9 个）

| FormList | 操作 |
|----------|------|
| `TMHA_AllHomeQuests` | 将 Quest 追加到末尾 |
| `TMHA_QuestHomeIndices` | 将 `TMHA_Index_{房产名}` 追加到末尾（顺序与 `TMHA_AllHomeQuests` 一致） |
| `TMHA_QuestStages` | 将 `TMHA_Stage_{房产名}` 追加到末尾（顺序一致） |
| `TMHA_AllHomeMarkers` | 将 XMarker 放入 **索引位置** |
| `TMHA_AllHomeNames` | 将 Message 放入 **索引位置** |
| `TMHA_AllHomeHolds` | 将 `TMHA_HoldIndex_{房产名}` 放入 **索引位置** |
| `TMHA_AllHomeLocationLists` | 将 `TMHA_Loc_{房产名}` 放入 **索引位置** |
| `TMHA_AllLocationsFlat` | 所有 Location 追加到末尾 |
| `TMHA_QuestMarkers` | 无需操作，保留旧数据即可（脚本不再读取） |

### 注意

- 如果新任务房产的 Quest 已经存在（如原版或 CC 的 Quest），只需在 `TMHA_AllHomeQuests` 中添加，无需新建。
- 任务阶段 `0` 表示 `IsCompleted()`，非 0 表示 `GetStage() >= 该阶段`。

## 六、距离型房产

### 需要创建的 CK 对象（共 4 个）

| 序号 | 类型 | EditorID 模板 | 说明 |
|------|------|---------------|------|
| 1 | Message | `TMHA_Name_{房产名}` | 房产显示名称 |
| 2 | GlobalVariable | `TMHA_HoldIndex_{房产名}` | 领地索引 |
| 3 | GlobalVariable | `TMHA_Index_{房产名}` | 统一房产索引 |
| 4 | XMarker | `TMHA_Marker_{房产名}` | 检测点（放置在门口，玩家靠近 300 单位内自动解锁） |

### 需要更新的 FormList（共 5 个）

| FormList | 操作 |
|----------|------|
| `TMHA_ProximityHomeIndices` | 将 `TMHA_Index_{房产名}` 追加到末尾（**顺序无关**） |
| `TMHA_AllHomeMarkers` | 将 XMarker 放入 **索引位置** |
| `TMHA_AllHomeNames` | 将 Message 放入 **索引位置** |
| `TMHA_AllHomeHolds` | 将 `TMHA_HoldIndex_{房产名}` 放入 **索引位置** |
| `TMHA_AllHomeLocationLists` | 将 `TMHA_Loc_{房产名}` 放入 **索引位置**（可选，用于排除） |

### 可选

| FormList | 操作 |
|----------|------|
| `TMHA_AllLocationsFlat` | 将所有 Location 追加到末尾（可选，用于判断是否在房产内） |

### 触发说明
- 玩家靠近 XMarker **300 游戏单位** 内时自动解锁。
- 不需要任何物品或任务。
- 距离检测每 2 秒运行一次，适合靠近即解锁的场景（如开放世界中的隐居点）。

## 七、通用注意事项

### 1. 索引管理
- 房产索引必须全局唯一，不能与其他房产（包括钥匙、任务、距离、炉火）的 `TMHA_Index_*` Value 重复。
- 炉火房产（索引 7~9）由脚本硬编码，**不要**为其他房产使用索引 7、8、9。

### 2. FormList 长度
- `TMHA_AllHomeNames`、`TMHA_AllHomeHolds`、`TMHA_AllHomeMarkers`、`TMHA_AllHomeLocationLists` 这四个 FormList 的长度应至少为 `最大索引 + 1`。例如，如果新索引是 17，这些 FormList 必须至少有 18 项（索引 0~17）。如果当前长度不足，通过在 CK 中“New”空项来扩展。
- `TMHA_AllLocationsFlat` 是扁平列表，没有索引要求，可以简单追加。

### 3. 顺序对齐（重要）
- `TMHA_KeyHomeIndices` 必须与 `TMHA_AllHomeKeys` 顺序完全一致。
- `TMHA_QuestHomeIndices` 和 `TMHA_QuestStages` 必须与 `TMHA_AllHomeQuests` 顺序完全一致。
- `TMHA_ProximityHomeIndices` 没有顺序要求。
- 四条统一 FormList（Names, Holds, Markers, LocationLists）**必须按房产索引顺序排列**，与 `TMHA_Index_*` 的 Value 一致。

### 4. 不需要修改脚本
- 所有 FormList 大小变化由脚本的 `OnUpdate` 自动检测，`BuildCache()` 自动重建缓存。
- 新增任何类型的房产都不需要重新编译或修改任何 `.psc` 文件。

### 5. xEdit 兼容性
- 当前设计已为 xEdit 自动化补丁做好准备：所有数据都在 FormList 中，索引由 GlobalVariable Value 控制。
- 未来可以用 PAScript 编写 xEdit 脚本，自动读取 `TMHA_AllHomeNames.GetSize()` 作为下一个索引，然后创建对象并填充 FormList。

## 九、常见问题

### Q：`TMHA_AllHomeMarkers` 中索引位置不正确怎么办？
A：在 CK 中打开该 FormList，找到对应位置，右键 → Delete 移除错误项，然后在正确位置 New 并拖入正确的 XMarker。或者使用 SSEEdit 直接编辑 FormList 顺序。

### Q：新房产解锁后没有出现在法术菜单中？
A：首先确认 `TMHA_UnlockedHomes` 中是否包含了该房产的 XMarker。可以在游戏控制台中输入 `help "TMHA_Unlocked" 4` 查看 FormList 内容。如果没有包含，请检查：
- `HomeUnlocked[索引]` 是否为 true（排查解锁条件）
- `CachedMarkers[索引]` 是否为空（排查 `TMHA_AllHomeMarkers` 填充）
- `UpdateUnlockedHomesFormList` 是否被调用（排查 `CheckForNew*` 函数是否执行）

### Q：距离房产的检测范围可以调整吗？
A：可以。修改 `TMHA_PlayerScript.psc` 中 `CheckProximityHomes` 函数里的 `300.0`，重新编译即可。建议保持默认。

### Q：我可以同时添加多个房产吗？
A：可以。只需要确保每个房产的索引不重复，并且所有 FormList 同步更新即可。

## 附录：快速检查清单（新增房产后）

- [ ] 房产索引已在 `TMHA_Index_{房产名}` 中正确设置
- [ ] 领地索引已在 `TMHA_HoldIndex_{房产名}` 中正确设置（对照领地表）
- [ ] `TMHA_AllHomeNames` 中对应索引位置有该房产的 Message
- [ ] `TMHA_AllHomeHolds` 中对应索引位置有该房产的 HoldIndex
- [ ] `TMHA_AllHomeMarkers` 中对应索引位置有该房产的 XMarker
- [ ] `TMHA_AllHomeLocationLists` 中对应索引位置有该房产的 Location 子表单（可选但建议）
- [ ] 如果是钥匙型：钥匙已加入 `TMHA_AllHomeKeys`，`TMHA_KeyHomeIndices` 顺序一致
- [ ] 如果是任务型：Quest 已加入 `TMHA_AllHomeQuests`，`TMHA_QuestHomeIndices` 和 `TMHA_QuestStages` 顺序一致
- [ ] 如果是距离型：`TMHA_ProximityHomeIndices` 已加入对应的 `TMHA_Index_*`
- [ ] `TMHA_AllLocationsFlat` 已包含所有 Location（可选但建议）
- [ ] 所有 FormList 长度至少为 `最大索引 + 1`
- [ ] 保存 `.esp`，重新加载存档，测试解锁
